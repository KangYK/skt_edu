# 고객지원 포털

납품한 웹 애플리케이션의 문의 접수·처리 현황·사용 가이드·유지보수를 관리하는 로컬 실행 서비스입니다. HTML/CSS/JavaScript와 Node.js 24+, SQLite로 구성했습니다. 별도 npm 패키지 설치가 필요하지 않습니다.

## 바로 체험하기

Windows에서 `시연실행.cmd`를 더블클릭한 뒤 http://127.0.0.1:4311 을 엽니다. 실행 창은 열어 둡니다. 가상 고객/고객사 담당자/유지보수 담당자/관리자 버튼으로 각 화면을 확인할 수 있습니다. 상단 역할 전환은 시연 환경에서만 표시됩니다.

터미널에서는 프로젝트 폴더에서 `node server/index.mjs --demo`를 실행합니다. 데이터는 `data/demo/portal.sqlite`에 저장됩니다. 시연에도 입력 내용이 저장되므로 가상 자료만 사용하세요.

## 실제 저장 서비스 시작

1. `서비스실행.cmd`를 실행합니다. 주소는 http://127.0.0.1:4310 입니다.
2. 별도 창에서 `관리자설정.cmd`를 실행하고 첫 관리자 이메일과 표시 이름을 입력합니다.
3. 표시된 1시간짜리 일회용 링크를 열고 본인의 비밀번호를 설정합니다. 초기 공용 비밀번호는 없습니다.
4. 관리자 화면에서 고객사 → 제품 → 사용자 초대 → 유지보수 담당 고객사 배정을 순서대로 설정합니다.
5. 초대 링크를 해당 사용자에게 직접 전달합니다. 이메일은 자동 발송되지 않습니다. 로컬 주소는 이 컴퓨터에서만 열 수 있으므로 다른 컴퓨터에서 사용할 때는 별도 서버 배포가 필요합니다.

관리자 링크가 만료됐거나 비밀번호를 잊은 경우 서버 파일에 접근할 수 있는 로컬 관리자가 `node --env-file-if-exists=.env scripts/setup.mjs --recover`를 실행해 새 링크를 발급할 수 있습니다. 일반 사용자는 관리자에게 재설정 링크를 요청합니다.

기본적으로 127.0.0.1에서만 접속됩니다. 다른 PC와 공유하거나 운영 배포하려면 인증 제공업체·HTTPS·운영 정책을 확정하고 아래 연결 항목을 완료해야 합니다.

## 역할과 권한

| 역할 | 문의 조회 범위 | 할 수 있는 일 |
|---|---|---|
| 고객 | 본인 접수 | 새 문의, 공개 답변, 첨부, 재개 요청 |
| 고객사 담당자 | 소속 고객사 전체 | 고객 문의 확인, 공개 답변 |
| 유지보수 담당자 | 배정된 고객사 | 상태·우선순위·담당자 변경, 공개 답변, 내부 메모 |
| 관리자 | 전체 | 고객사·제품·계정·권한·배정·콘텐츠 관리 |

모든 문의/댓글/첨부 경로에서 서버가 권한을 검사합니다. 내부 메모와 해당 이력은 외부 고객에게 반환하지 않습니다. 권한 변경·비활성화·비밀번호 재설정 시 기존 세션이 만료됩니다. 접수 이력이 있는 사용자 계정은 다른 고객사로 이동할 수 없습니다.

## 구현한 기능

- 이메일·비밀번호 로그인, 해시된 비밀번호 저장, HttpOnly 세션 쿠키, CSRF 확인, 로그인 시도 제한.
- 일회용 초대·재설정 링크(1시간), 사용자 활성/비활성, 역할 변경과 고객사 배정.
- 문의 생성·검색·필터, 접수 중복 방지, 상태 전환, 동시 변경 충돌 확인, 담당자 배정.
- 공개 답변, 내부 메모, 완료 후 재개 요청, 처리 이력.
- 문의당 5개까지 PNG/JPG/UTF-8 TXT 첨부, 각 2MB 제한. 파일 시그니처 또는 UTF-8 텍스트 형식 확인. 다운로드 시 서버 권한 확인 및 강제 다운로드.
- 고객사/제품별 가이드·공지·FAQ 게시와 유지보수 범위 편집.
- 데스크톱/모바일 화면, 로컬 Pretendard 폰트.

## 저장·백업·복원

실제 데이터는 `data/live/portal.sqlite`, 시연 데이터는 `data/demo/portal.sqlite`에 분리됩니다. 문의·첨부 바이트·계정·권한·이력은 SQLite에 함께 저장됩니다. DB 파일을 열 때 환경 표시가 일치하지 않으면 실행을 거부합니다.

백업: `node --env-file-if-exists=.env scripts/backup.mjs`. `backups/`에 일관된 SQLite 백업이 생성됩니다. 첨부도 포함합니다.

복원은 서비스를 종료한 상태에서 진행하세요. 현재 데이터 폴더 전체를 별도 보관한 뒤 **새 데이터 폴더**에 백업 파일을 `portal.sqlite`라는 이름으로 복사하고 `.env`의 `DATA_DIR`을 새 폴더로 지정합니다. 이전 DB의 `-wal`, `-shm` 파일과 섞지 마세요. 복원 후 계정·문의·첨부를 확인합니다. 백업에는 계정 정보와 세션도 포함되므로 파일 접근을 제한하고, 필요하면 복원 후 해당 계정을 비활성/활성 처리해 세션을 폐기합니다.

`data/`, `backups/`, `.env`, 데이터베이스 파일은 Git 제외 대상입니다. 서버 또는 사용자 데이터는 GitHub에 올리지 마세요.

## 실행 명령

```powershell
node server/index.mjs --demo
node --env-file-if-exists=.env server/index.mjs
node --env-file-if-exists=.env scripts/setup.mjs
node --test tests/portal.test.mjs
node --env-file-if-exists=.env scripts/backup.mjs
```

Node가 PATH에 없다면 Windows 실행 파일이 이 PC의 Codex 제공 Node를 찾습니다. 다른 PC에서는 Node.js 24 이상을 설치하세요. `package.json`에도 같은 npm 명령을 제공하지만 npm은 필수가 아닙니다.

## 로컬 구현과 운영 연결의 경계

- 사용자의 요청에 따라 로컬 실행부터 완성했습니다. 공개 배포는 하지 않았습니다.
- 회사 계정 로그인(OIDC/SAML)은 아직 연결하지 않았고 UI에서 비활성 상태로 표시합니다. 이메일 로그인은 실제 동작합니다.
- 외부 이메일 발송, 기존 고객 관리 시스템 연결은 미구현입니다. 선택한 제공업체의 설정과 API가 필요합니다.
- 현재 첨부는 제한된 형식만 허용하고 파일 시그니처를 검사합니다. 악성코드 검사 엔진은 연결하지 않았으므로 외부 고객용 운영 전 별도 스캐너 연동이 필요합니다.
- 유지보수 계약·지원 시간·응답 기한·보관 및 삭제 정책은 운영자가 확정해야 합니다. 고객사별 계약 화면에서 안내를 입력할 수 있습니다.
- SQLite 단일 서버 구성입니다. 여러 서버나 대규모 운영을 계획하면 PostgreSQL·비공개 객체 저장소로 이전하고 DB 마이그레이션 및 모니터링을 준비하세요.
- 외부 공개 시 HTTPS 역방향 프록시, `NODE_ENV=production`, HTTPS `APP_ORIGIN`, `SECURE_COOKIES=true`, 제한된 DB 파일 권한, 백업 운영 설정이 필요합니다. SSO 제공업체, 운영 침투/부하 테스트는 아직 검증하지 않았습니다.

## 검증

`node --test tests/portal.test.mjs`: 고객사 격리, 내부 메모, 직접 첨부 접근 차단, 상태/동시 변경, 초대·재설정, 권한 변경, DB 재시작 유지, 첨부 포함 백업 복원, 시연/실제 분리를 검증합니다.

브라우저에서 가상 문의 접수·공개 답변·담당자 배정·상태 변경을 확인했습니다. 1280px 대시보드와 375px 문의 상세/관리 화면을 확인했습니다. 캡처는 `screenshots/`에 있습니다.

참고: [Node.js SQLite 공식 문서](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html). 폰트 라이선스는 `public/fonts/LICENSE.txt`입니다.
